# My Contribution and Collaboration Scope

## 프로젝트 성격

이 프로젝트는 경진대회 팀 프로젝트다. 분석 결과와 제출물 전체를 개인 단독 성과로 주장하지 않는다. 이 문서는 `@minster0422`가 수행한 검토·수정·커뮤니케이션 작업과 포크 이후 개인 개선을 구분하기 위해 작성했다.

## 대회 제출 과정에서 수행한 일

### 1. 평가기준을 검증 질문으로 변환

서면평가 6대 항목을 단순 목차가 아니라 다음 확인 질문으로 바꿨다.

- 공정변수와 라벨의 분석단위가 일치하는가?
- 같은 작업일의 행이 학습·평가에 동시에 들어가는가?
- 합성 이상 성능을 실제 불량 탐지율로 표현하지 않았는가?
- FN·FP 비용과 임계값이 관측 근거를 갖는가?
- 보고서 수치가 코드와 원본 CSV까지 추적되는가?
- 빈 환경에서 전처리부터 검증까지 다시 실행되는가?

### 2. 제출 직전 P0/P1 감사

- 매니페스트의 `UNKNOWN`, `MISSING`, `STALE` 실패 판정 확인
- 검사기 산출물의 자기참조 제외와 외부 검증 파일의 정확한 파일명 판정 확인
- Monte Carlo 순열검정의 +1 보정 산식 확인
- 컨포멀 임계를 확정적 보장이 아닌 명목 임계·근사 운영 후보로 하향 표현
- Jackknife+ 구간의 명목 수준과 일반 유한표본 보장 하한 구분

### 3. 기술 커뮤니케이션

- 합성 이상, 실제 운전, 실제 불량, 외부 실제라벨의 증거 수준을 분리
- 0.971을 실제 용접불량 탐지율로 표현하지 않도록 문구 정정
- 일 단위 3/3 경보가 불량 발생이 아니라 공정 이동 탐지임을 명시
- 장문 기술 원고를 평가자가 빠르게 읽을 수 있는 결과보고서와 발표 흐름으로 압축

### 4. AI 보조 교차검증

생성형 AI를 결론 생성기가 아니라 반론 생성기로 사용했다. AI/ML, 용접 도메인, 데이터 엔지니어링, 공장 운영·비용, 서면평가의 5개 관점으로 같은 주장을 공격하게 한 뒤 실제 코드, CSV, 보고서, 재실행 결과로 판정했다.

## 포크 이후 개인 개선

- 채용·대학원 평가자를 위한 `PROJECT_CARD.md` 추가
- 개인 기여와 팀 결과를 분리한 공개 문서 추가
- 원본 데이터 없이 실행할 수 있는 `tools/portfolio_quality_gate.py` 추가
- GitHub Actions에서 구문·P0/P1 안전장치·상대 링크·원본 데이터 제외 여부 자동 검사

## 의도적으로 주장하지 않는 것

- 전체 모델링 코드를 혼자 설계·구현했다는 주장
- 합성 AUC 0.971이 실제 불량 탐지 정확도라는 주장
- 현장 비용절감액과 불량 저감 효과가 확정됐다는 주장
- 경진대회 수상이나 순위에 대한 확인되지 않은 주장
