# AI-assisted Review and Prompt Design

생성형 AI는 모델 성능을 대신 판단하는 도구가 아니라 반론 생성, 누락 탐색, 제출물 감사에 사용했다. 최종 판단은 코드, CSV, 재실행 로그와 문서 원문을 대조해 내렸다.

## 다섯 개 검토 관점

1. AI/ML — 누수, 과적합, 중첩 교차검증, 확률보정
2. 용접 도메인 — 전류·전압·가압력·통전시간과 물리 파생변수
3. 데이터 엔지니어링 — 원클릭 실행, 의존성, 매니페스트와 파일 해시
4. 공장 운영 — 미탐지·오경보 비용, 임계값과 시범운용 범위
5. 보고서 평가 — 평가기준 충족, 수치 근거, 블라인드와 과장 표현

## 사용한 프롬프트 구조

```text
[역할]
당신은 제조 AI 경진대회의 심사위원이자 재현성 감사자다.

[청중]
산·학·연 심사위원과 현장 품질 담당자가 읽는다.

[판정 기준]
데이터 이해, 모델 개발, 오류분석, 현장 활용, 차별성, 재현성을 각각 평가한다.

[강제 검증]
- 실제 파일명·함수명·산출물로만 주장한다.
- 합성 성능과 실제 불량 성능을 구분한다.
- 행 무작위 분할과 작업일 그룹 분할을 비교한다.
- 실패한 접근과 비유의 결과를 숨기지 않는다.
- 수정안은 P0/P1 우선순위와 확인 방법까지 제시한다.

[출력]
근거 → 위험 → 수정 → 재검증 결과 순으로 작성한다.
```

## AI 제안을 반영하지 않은 사례

- 동적 패치 트랜스포머는 연속 조기징후 라벨이 없어 제출 시점에 구현하지 않았다.
- 합성 AUC를 실제 불량 예측 정확도로 표현하지 않았다.
- 현장 단가와 불량 농축배수가 없어 비용절감액을 확정값으로 제시하지 않았다.
- 근거 원문을 확인하지 못한 외부 규격을 임의로 인용하지 않았다.

프롬프트의 목적은 좋은 문장을 얻는 것이 아니라, 틀릴 가능성이 높은 주장을 먼저 공격하게 만드는 것이었다.
